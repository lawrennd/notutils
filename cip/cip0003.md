# CIP-0003: Migrate from Poetry to uv

## Status
- [x] Proposed
- [x] Accepted
- [x] In Progress
- [ ] Implemented
- [ ] Closed

## Summary
Replace Poetry with [uv](https://docs.astral.sh/uv/) as the project's package and dependency manager. Convert `pyproject.toml` to PEP 621 project metadata, replace `poetry.lock` with `uv.lock`, and update GitHub Actions and contributor docs so install, test, lint, and docs builds use `uv` instead of `poetry`.

## Motivation
notutils currently uses Poetry for dependency declaration, locking, local development, and CI (`snok/install-poetry`, `poetry install`, `poetry run`). Poetry works, but uv is substantially faster for resolve/install, has become a common default in the Python tooling ecosystem, and aligns local and CI workflows around a single lightweight binary.

Practical pain points with the current setup:
1. **CI latency**: Every workflow installs Poetry before installing the project; uv setup is typically a single action plus `uv sync`.
2. **Dual mental model**: Contributors who already use uv elsewhere must also know Poetry commands for this repo.
3. **Non-standard metadata**: `[tool.poetry]` is Poetry-specific; PEP 621 `[project]` metadata is the shared standard and is what uv (and most modern backends) expect.
4. **Stale classifiers**: Project classifiers still advertise Python 3.6 while dependencies require `>=3.9` — a good moment to correct metadata while rewriting `pyproject.toml`.
5. **Untracked lockfile**: `poetry.lock` was gitignored, so CI cache keys on a file that was not shared across clones.

This CIP is scoped to **notutils**. The sibling `mlai` package has the parallel design in [CIP-0009](https://github.com/lawrennd/mlai/blob/main/cip/cip0009.md) (contributor packaging via uv).

## Detailed Description

### Target packaging shape
Move from Poetry's proprietary table layout to:

| Concern | Poetry today | uv target |
|---|---|---|
| Project metadata | `[tool.poetry]` | `[project]` (PEP 621) |
| Runtime deps | `[tool.poetry.dependencies]` | `[project.dependencies]` |
| Dev deps | `[tool.poetry.group.dev.dependencies]` | `[dependency-groups]` `dev` (PEP 735) |
| Build backend | `poetry-core` | `hatchling` |
| Lockfile | `poetry.lock` (gitignored) | `uv.lock` (committed) |
| Local install | `poetry install` | `uv sync` |
| Run tools | `poetry run pytest` | `uv run pytest` |

`[tool.uv] default-groups = ["dev"]` so `uv sync` matches the previous `poetry install --with dev` contributor experience.

Keep existing `[tool.pytest.ini_options]` and `[tool.coverage.*]` sections unchanged.

### Dependency resolution policy
- Preserve the current dependency *set* (runtime and dev); do not use this CIP to add or remove packages.
- Translate Poetry caret ranges (`^7.0.0`) to equivalent PEP 440 ranges (`>=7.0.0,<8`).
- Wildcard runtime pins remain unconstrained unless `uv lock` forces a tighten.
- Commit `uv.lock` so CI and contributors share the same resolved set.

### CI changes
Update `.github/workflows/{test,lint,docs}.yml` to:

1. Install uv via `astral-sh/setup-uv@v6`.
2. Use `uv sync` (dev group is default) instead of `poetry install --with dev`.
3. Rely on setup-uv caching rather than a custom Poetry venv cache keyed on `poetry.lock`.
4. Replace `poetry run …` with `uv run …`.

Matrix Python versions remain `3.9`–`3.12` for test and lint; docs stay on `3.11`.

### Docs and contributor surface
Update `README.md`:
- `uv sync` / `uv run pytest` for contributors
- Keep `pip install notutils` for end users
- Optional `uv add notutils` for uv consumers

### What we remove
- Local `poetry.lock` artefact (already untracked)
- `[tool.poetry]` tables and `poetry-core` build backend
- Poetry install steps in workflows
- Poetry-first contributor docs

### Out of scope
- Migrating `mlai` (see mlai CIP-0009)
- Changing runtime API or package version scheme
- Redesigning the test suite (CIP-0002)
- Implementing the PyPI release workflow (separate backlog item); when that lands, use `uv build` / `uv publish`

## Implementation Plan

1. **Convert project metadata**
   - Rewrite `pyproject.toml` to PEP 621 + hatchling
   - Map runtime and `dev` dependency groups
   - Correct Python classifiers / `requires-python` consistency (`>=3.9`)

2. **Lock and verify locally**
   - Run `uv lock` and `uv sync`
   - Confirm `uv run pytest` passes with the existing coverage gate
   - Confirm `uv run mypy` and docs build still work

3. **Update CI**
   - Replace Poetry setup in `test.yml`, `lint.yml`, and `docs.yml`
   - Confirm matrix still covers 3.9–3.12

4. **Update documentation**
   - README install/dev sections
   - Point `setup.py` at PEP 621 / uv rather than Poetry

5. **Remove Poetry artefacts**
   - Delete local `poetry.lock` if present
   - Grep for remaining contributor-facing `poetry` references

## Backward Compatibility
- **End users** installing via `pip install notutils` are unaffected.
- **Contributors** must install uv instead of Poetry.
- **Published package metadata** remains a standard wheel/sdist; only the *authoring* tool changes.
- No import-path or API changes.

## Testing Strategy
- Local: `uv sync` then `uv run pytest` (coverage ≥ 80%).
- Local: `uv run mypy notutils/notutils.py --ignore-missing-imports`.
- Local: docs HTML build via `uv run make html` in `docs/`.
- CI: all three workflows green on the CIP branch PR.
- Smoke: `uv build` produces sdist and wheel containing the `notutils` package.
